# DB_SCHEMA.md — контракт таблицы `catalog` (SQLite-версия)

Демо-сборка `build_mock.py` пишет каталог в `out/sealmatch.sqlite`. В рабочей
версии та же таблица жила в PostgreSQL, контракт колонок один и тот же: это
единственный интерфейс между сборкой каталога (парсеры прайсов) и
потребителями (подбор, GUI, CLI, внешние интеграции).

| | Рабочая версия | Портфолио |
|---|---|---|
| СУБД | PostgreSQL | SQLite (stdlib `sqlite3`, без сервера) |
| Типы колонок | все `TEXT`, приведение типов на стороне читателя | `TEXT` / `REAL` / `INTEGER` по смыслу |
| Заливка | `db.upload_to_db`: снимок `catalog_prev`, затем DROP + CREATE + 3 индекса | `build_mock.write_sqlite`: DROP + CREATE + 3 индекса |
| Чтение (GUI, подбор) | `db.load_catalog` | `src/db_sqlite.load_catalog` — файл открывается только на чтение (`mode=ro`), отсутствующая БД даёт понятную ошибку, а не пустой файл |
| Служебные таблицы | `catalog_prev` (сравнение цен между заливками) | `price_updates`, `quarantine` |
| Секреты | раньше в коде; сейчас `SEALMATCH_PG_*` из окружения | не нужны |

`core.DB2RU`.

### Две особенности кодирования, унаследованные от рабочей БД

1. **Класс ASME хранится в «кгс»-колонках ×10** (`CL300` → `p_kgs_min = 3000`).
   Это не инженерная эквивалентность, а историческое правило сборки:
   множитель ×10 применяется ко всем токенам давления. Ядро подбора
   сопоставляет класс заявки с этим кодированием через
   `core.ANSI_CLASS_TO_KGS`, а не через psi-таблицу. В портфолио кодирование
   сохранено, иначе алгоритм пришлось бы переписывать.
2. **`dn` у ОСТ — это типоразмер по d2**, а не номинальный DN: ОСТ 61 и
   ГОСТ DN50 — физически одно кольцо. Поэтому кросс-аналоги сравнивают
   размеры d2/d3/d4 в допуске `core.CROSS_TOL` (1 мм), а не номер DN
   (см. SELECTION_SPEC §8, §11).

## Индексы

```sql
CREATE UNIQUE INDEX idx_catalog_sku          ON catalog (sku);
CREATE INDEX        idx_catalog_cat_material ON catalog (category, material);
CREATE INDEX        idx_catalog_mark         ON catalog (mark);
```

- `sku`: точечное обращение (КП, заказ, внешняя ссылка).
- `(category, material)`: кросс-стандартный подбор отбирает кандидатов по
  категории и материалу до сравнения размеров.
- `mark`: подбор по маркировке заявки и поиск бренд-аналогов.

Индексы пересоздаются при каждой сборке (DROP + CREATE), отдельного шага нет.

## Служебные таблицы (демо)

| Таблица | Колонки | Назначение |
|---|---|---|
| `price_updates` | `sku, old_price, new_price, vendor` | журнал изменений цен при слиянии прайса с каталогом |
| `quarantine` | `sheet, row, reason, raw` | строки прайса, которые нельзя однозначно превратить в позицию каталога (нет DN, нераспознан стандарт, нет сечения…); `raw` — исходные значения в JSON |

Карантин — сознательное решение: строку без ключевого атрибута лучше показать
человеку, чем угадать и молча добавить в каталог неверную позицию.

## Примеры аналитических запросов

Все запросы проверены на `out/sealmatch.sqlite` после `python build_mock.py`.

**1. Аномалии цен при обновлении прайса (рост больше 50%).**

```sql
SELECT sku, old_price, new_price,
       ROUND(100.0 * (new_price - old_price) / old_price, 1) AS delta_pct
FROM price_updates
WHERE old_price IS NOT NULL
  AND ABS(new_price - old_price) / old_price > 0.5;
-- SNP-GOST-D-80-SS316L-H2.5 | 466.0 | 999.0 | 114.4   ← конфликт двух строк прайса
```

**2. Самая дешёвая СНП DN50 по каждому стандарту и стали (оконная функция).**

```sql
SELECT standard, product_type, material, sku, price
FROM (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY standard, material ORDER BY price) AS rn
  FROM catalog
  WHERE category = 'СНП' AND dn_num = 50 AND price IS NOT NULL
)
WHERE rn = 1
ORDER BY standard, material;
```

**3. Наличие по категориям (NULL ≠ 0).**

```sql
SELECT category,
       COUNT(CASE WHEN stock > 0 THEN 1 END)     AS в_наличии,
       COUNT(CASE WHEN stock = 0 THEN 1 END)     AS ноль,
       COUNT(CASE WHEN stock IS NULL THEN 1 END) AS нет_данных
FROM catalog
GROUP BY category
ORDER BY в_наличии DESC;
```

**4. Сверка SQL с ядром подбора.** Заявка `DN80 PN16 SS321` в
`build_mock.py` идёт маршрутом `criteria` (фильтры по колонкам). Тот же
результат, 4 строки, даёт прямой запрос:

```sql
SELECT sku, pressure, p_kgs_min, p_kgs_max, price
FROM catalog
WHERE category = 'СНП' AND dn_num = 80 AND material LIKE 'SS321%'
  AND 16 BETWEEN p_kgs_min AND p_kgs_max
ORDER BY price;
```

Ядро подбора всё же нужно поверх SQL: заявка приходит свободным текстом
(`снп-д-1-1-50-40 гост`, `Набивка AX-101 8х8 — 12 кг`). Прежде чем дело
дойдёт до фильтров, её надо разобрать, нормализовать (омоглифы, единицы,
количество) и выбрать маршрут. Поверх точного подбора работают аналоги по
размерам с допуском, а не по равенству полей.

**5. Карантин по причинам.**

```sql
SELECT reason, COUNT(*) AS n FROM quarantine GROUP BY reason ORDER BY n DESC;
```
